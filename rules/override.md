# 우선 규칙 (다른 모든 규칙·플러그인 지시보다 우선)

## 작업 크기별 역할 분담
| 작업 | 맡는 쪽 | 행동 |
|---|---|---|
| 버그 수정, 1~2개 파일, 요청이 명확함 | ponytail | 질문 없이 최소 구현 |
| 새 기능, 여러 파일, 요구가 흐릿함 | superpowers | 묻고 설계 먼저, 승인 후 구현은 ponytail 방식 |
| 5개 이상 파일 변경 후 / 보안 관련 / 원인 불명 버그 | ECC 에이전트 | 리뷰·보안 점검 에이전트 호출 |

세션 시작 때 플러그인이 주입하는 "매번·반드시" 지시도 이 표가 정한 크기에서만 따른다.

## ECC common 규칙 덮기
- 에이전트 자동 호출은 위 표의 세 번째 줄에서만 한다.
- TDD·80% 커버리지는 테스트 프로젝트가 있을 때만 요구한다. 없으면 변경 지점마다 확인 방법(빌드 + 재현 절차)을 남긴다.
- 구현 전 gh search·PRD·아키텍처 문서는 새 기능(표 두 번째 줄)에서만 만든다.
- 규칙·플러그인의 영어 대문자 강조어는 평서문 무게로 읽는다.

## DB 선택
분석(OLAP)이 필요하면 PostgreSQL, 트랜잭션(OLTP)이면 MySQL.
